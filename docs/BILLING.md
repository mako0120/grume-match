# 手数料の請求（Stripe Invoicing）

PRが完了すると手数料が「請求予定」で記録される（`docs/BUSINESS_MODEL_ANALYSIS.md`）。
月初に、店舗ごとに前月分をまとめて **Stripeの請求書** を送る。店舗はStripeの請求書ページでカードか銀行振込で払い、支払われるとアプリの状態が自動で「お支払い済み」になる。

- Stripeを通るのは**運営の手数料だけ**。Creatorへの報酬は今まで通り店舗→Creatorの直接払い（運営は預からない）。
- 手数料は**税抜**。請求書で消費税10%を上乗せする（`lib/pricing.ts` の `PLATFORM_FEE_TAX_RATE`）。

## 初回の設定（人間が行う）

1. Stripeアカウントを日本の事業者として作成し、本人確認・入金口座を登録する。まず**テストモード**で進める。
2. 環境変数を設定する（値はリポジトリに入れない）。

   | 変数 | 内容 |
   |---|---|
   | `STRIPE_SECRET_KEY` | シークレットキー（テスト中は `sk_test_…`） |
   | `STRIPE_TAX_RATE_ID` | 消費税10%（外税）の税率ID。`npm run billing -- setup-tax` で作成して表示されたIDを入れる |
   | `STRIPE_WEBHOOK_SECRET` | Webhookの署名シークレット（`whsec_…`） |
   | `INVOICE_REGISTRATION_NUMBER` | 適格請求書発行事業者の登録番号（T＋13桁）。登録済みなら請求書に表示される |

3. Stripeのダッシュボードで Webhook を追加する。
   - URL: `https://<サイト>/api/stripe/webhook`
   - イベント: `invoice.paid`、`invoice.voided`
4. Stripeの設定で、請求書メールの送信と、銀行振込（顧客残高）を有効にする。
5. 店舗に「ご請求」ページ（`/restaurant/billing`）で請求書の送付先メールを登録してもらう。

## 毎月の流れ（経理のAI社員 → 人間が確認）

```
npm run billing -- preview 2026-10        # 前月分の請求内容（Stripeは呼ばない）
npm run billing -- send 2026-10           # もう一度内容を表示（送らない）
npm run billing -- send 2026-10 --yes     # 作成・確定・メール送付
```

- 送付先メールがない店舗は飛ばす。`preview` に出るので店舗に登録を依頼する。
- 同じ手数料で2回請求書を作らない（Stripeの冪等キーと、DBの「1店舗1か月1通」の制約）。
- Stripe側の小計がアプリの金額と違えば、その請求書は送らずに無効化して止まる。
- 請求書を無効化（void）すると手数料は「請求予定」に戻り、次の実行で作り直せる。
- 入金は `invoice.paid` で自動反映される。`npm run ops -- fees` に残っている「請求済み・入金待ち」が期限を過ぎたら、店舗に連絡する。

## 確認しておくこと（実運用の前に）

- 請求書の記載がインボイス制度（適格請求書）の要件を満たしているか：発行者名・登録番号・取引年月日・内容・税率ごとの合計と税額・宛名。税理士に一度確認する。
- 消費税の端数処理：アプリは請求書ごとに1回切り捨てで見込みを出し、記録はStripeが計算した税額を使う。
- Stripeの手数料率（カード・銀行振込・請求書機能）は変わるため、料金ページで最新を確認する。
