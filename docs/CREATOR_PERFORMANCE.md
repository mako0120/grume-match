# PROOF — Creator performance

フォロワー数ではなく「直近30日に実際どれだけ見られたか」で選ばれるようにする機能。
Creatorがインサイトの数字を貼り付けると、30日サマリーが自動で作られ、次の場所で使われる。

| 場所 | 誰が見る | 内容 |
|---|---|---|
| `/creator/performance` | Creator本人 | スクショ送信・実績の確認 |
| 応募者を選ぶ画面 | 店舗 | 応募者ごとの「30日 ◯閲覧・中央値・反応率・確認済」 |
| 指名オファーのCreator選択 | 店舗 | 同上。中央値の大きい順に並ぶ |
| `/restaurant/creators/[id]` | 店舗 | フルのメディアキット＋「この人に指名オファー」 |
| `/admin/performance` | 運営 | スクショを見て数字を登録 → 運営確認済み |

## Creatorがやること

`/creator/performance` でインサイト → コンテンツ → 30日間 → 閲覧数順の画面を撮って送るだけ（月1回）。数字の入力は不要。手入力したい場合は「自分で数字を入力する」を開く。

## スクショの読み取り（APIなし・Claudeが随時判断）

外部のOCRやAI APIは使わない。送られたスクショは「読み取り待ち」になり、次のどちらかで登録する：

- **Claudeに頼む**：「実績スクショを読み取って」。Claudeは `.claude/skills/read-insights/SKILL.md` の手順で
  `npm run insights -- list` → 画像を見て書き起こし → `submit`（プレビューで照合）→ `--yes` で登録する。
  読めない場合は理由付きで差し戻す。必要な環境変数は `NEXT_PUBLIC_SUPABASE_URL` と `SUPABASE_SECRET_KEY`。
  定期的に処理したい場合は、Claude Codeのスケジュール実行（Routine）でこの依頼を毎日実行できる。
- **運営が画面で入力**：`/admin/performance` でスクショを見ながら同じ形式で入力して登録。

どちらも登録した数字は「運営確認済み」になり、Creatorに通知される。

## 入力形式（Claude・運営・手入力共通）

インサイト → コンテンツ → 30日間 → 閲覧数順 の画面を見ながら、1投稿1行：

```
エリア / 見出し / 閲覧数 / いいね / コメント / リポスト / シェア / 投稿時期
```

- 「2.7万」「1,106」「3週間」「4日」はそのまま入力できる（万表示は「約」付きの概数として扱う）
- 見出しは省略可。行のどこかに `https://` の投稿URLを入れるとリンクになる
- 区切りは ` / `・タブ・`|`（使わない場合は空白）。カンマは桁区切りとして読む
- 同じSNS・同じ計測日を再保存すると置き換え。月1回更新する（35日を過ぎると「更新待ち」表示）

自動で作られるサマリー（`tests/creator-performance.test.mjs` で固定）：

- 直近30日の8投稿で合計約12.4万閲覧（平均1.6万・中央値1.2万・最高2.7万）
- 全投稿が5,000閲覧以上
- 8本中5本が1万閲覧超え
- 最高約2.7万閲覧（淡路市・小野原）
- 8エリアで実績（大阪市内・北摂・南河内・淡路島）

運営確認を付けるには、同じ画面のスクリーンショットを「運営確認」から送る。

## プライバシーと信頼性

- 数値は自己申告。運営がスクリーンショットと照合したものだけ「運営確認済み」。編集すると確認は外れる
- スクリーンショットはCreator本人と運営だけが見られる（オーディエンス情報が写ることがあるため店舗には出さない）
- 店舗が見られるのはログイン中の有効な店舗アカウントのみ（Creator同士・未ログインは不可）
