# 企業分析 — 競合はどうやって成り立っているか

調査日: 2026-10-03。各社の公開情報・プレスリリース・比較記事から整理した（出典は末尾）。
売上・店舗数などの非公開の数字は推測しない。**「試算」と書いた数字は仮定にもとづく計算例で、各社の実績ではない。**
サービス比較は `docs/COMPETITIVE_ANALYSIS.md` を参照。

## 1. 共通する稼ぎ方

ほぼ全社が **「店舗からお金をもらい、インフルエンサーには現金を払わない（食事・商品で対価を払う）」** 形で成り立っている。

```
店舗 ──月額・初期費用──▶ プラットフォーム
店舗 ──料理を無料提供──▶ インフルエンサー ──投稿──▶ 店舗の集客
```

- 供給側（インフルエンサー）の獲得コストが安い：食べ歩きが好きな人は「無料で食べられる」だけで登録する。登録無料・フォロワー100人から可、のように間口を広げて**数（1万人以上）**を集める。
- 料理の原価は店舗が負担するので、**プラットフォームの原価はほぼシステムと営業だけ**。月額課金なら粗利率が高い。
- 弱点も共通：成果（来店）が見えにくく、解約されやすい。そのため各社は「分析」「AI」「通販案件」などの**追加価値**で引き留めに動いている。

### グルキャス／PR会社・総合DX（GATEなど）
- グルキャス：キャスティング＋集客コンサルの**個別見積**。業界相場では来店型PRが1人3〜30万円。
- 従来型のPR会社：店舗が3〜15万円程度を支払い、インフルエンサーは無償飲食、という形が2022年以前の主流。
- GATE：予約・会計・CRMなど外食DXの一部としてインフルエンサー施策を提供。**単体ではなくパッケージで売る**。

## 3. 型ごとの比較

| 型 | 代表 | 店舗の支払い | インフルエンサーへの現金 | 強み | 弱み |
|---|---|---|---|---|---|
| 定額し放題 | ユニット・tags | 月3〜8万円 | 原則なし | 継続課金・高粗利・人数 | 成果が見えず解約されやすい |
| 超低価格 | QUANT | 月5,000円 | なし | 既存の供給を流用 | 大手の資産がないと真似できない |
| フリーミアム | モグカツ | 0円〜8万円 | なし | 間口が広い・周辺サービスへ拡張 | 無料利用者が多いと収益化が遅い |
| 1件課金 | FOODee IM・グルキャス | 1人数万〜数十万円 | あり（費用の中から） | 単価が高い・質を担保しやすい | 人手がかかり、件数が伸びにくい |

## 4. GOURMET DIARY への示唆

### 前提が違う
私たちは**現金報酬が必須**なので、店舗はすでにCreatorにお金を払っている。競合と同じ「月3万円・依頼し放題」を上乗せすると、店舗の総額が高くなりすぎる。
→ **月額し放題では戦わず、「1件ごと」と「成果」で課金する**のが自然。

### 料金案（試算）
前提：大阪の1店舗が月2件、現金報酬8,000円（税込）でPRを実施。

| 案 | 中身 | 店舗の月額総額 | 運営の売上/店 |
|---|---|---|---|
| A 手数料型 | 報酬の20%を店舗から手数料 | 16,000＋3,200＝**19,200円** | 3,200円 |
| B 月額＋手数料 | 月9,800円＋報酬の10% | 16,000＋9,800＋1,600＝**27,400円** | 11,400円 |
| C 来店成果型 | 手数料10%＋PRコードで記録された来店1件500円 | 16,000＋1,600＋来店数×500円 | 1,600円＋来店連動 |
| 参考：ユニット | 月3万円（Creatorは無償） | 30,000円＋料理原価 | 30,000円 |

- どの案も店舗の総額は競合の月額と同じくらいだが、**Creatorに現金が渡り、来店単価まで見える**のが違い。
- 運営の売上は競合より小さい。100店で月2件ずつ：A案 月32万円、B案 月114万円（仮定の計算）。**パイロット期はA案で始め、店舗が増えたらB案（月額）を足す**のが現実的。
- C案はSIGNAL（来店計測）があるからできる、私たちだけのメニュー。データがたまってから試す。
- 追加の収益源：UGC二次利用料の手数料、急募（FLASH）の手数料上乗せ。

### 決定（2026-10-03）：A案を改良した「完了時だけの手数料」

| 項目 | 内容 |
|---|---|
| 初期費用・月額 | 0円 |
| 案件の種類 | **食事招待のみ**（現金報酬0円）か **食事＋現金報酬** を店舗が選ぶ（2026-10-03追加） |
| 手数料 | PRが**完了した時だけ**（投稿を承認した時）、Creatorへの支払額（報酬＋二次利用料）の**20%、最低¥2,000**。食事招待のみは¥2,000 |
| 初回 | 各店舗の**最初に完了した1件は手数料無料** |
| Creator | 報酬を全額受け取る（Creator側の手数料なし） |
| 請求 | 運営が月ごとにまとめて店舗へ請求（アプリ外）。アプリは記録と状態（請求予定→請求済み→お支払い済み）だけ持つ |

初期の価値（2026-10-03 オーナー判断）：
- 店舗：**広告費をかけずに**、料理の提供だけでPR投稿を作ってもらえる。
- Creator：**無料でご飯が食べられる**。これだけで参加する人は多い（競合が1万人以上集めている理由と同じ）。
- 現金報酬つきは、実績のあるCreatorを確実に呼びたい店舗向けの上位の選択肢にする。

選んだ理由：
1. **競合と同じ土俵に乗らない**：月3万円の定額や月5,000円の依頼し放題とは、比べられない形にする。店舗は「使った分だけ、成果が出た分だけ」払う。
2. **完了しなければ0円**：投稿されない・来ないリスク（業界の不満）を運営が負う形になり、営業で一番強い言葉になる。
3. **最低¥2,000**：報酬が低い案件でも運営の手間（AI社員の確認・連絡）を賄う。報酬¥8,000で手数料¥2,000、¥15,000で¥3,000。
4. **初回無料**：導入の壁を下げる。1件目で来店単価・1,000閲覧あたり費用を見てもらい、2件目から有料。
5. **資金を預からない**：店舗→Creatorの報酬は今までどおり、運営は手数料を別に請求するだけ。収納代行・資金移動の法的論点を避けられる。

見直す条件：店舗が月3件以上を継続するようになったら、B案（月額＋低い手数料）を選択肢として追加する。C案（来店成果型）はPRコードの来店記録が十分たまってから検証する。

実装：`lib/pricing.ts`、`supabase/migrations/202610030008_platform_fees.sql`（支払いが承認された時に記録、初回は自動で無料）、店舗の `/restaurant/billing`、経理キュー `npm run ops -- fees`。

### 守るべき点
- **資金の流れ**：店舗の支払いを運営が預かってCreatorへ渡す形にすると、資金移動・収納代行の法的確認が必要。パイロットは現状どおり手動振込とし、Stripe Connect等は確認後に導入（`docs/ROADMAP.md` Phase 3）。
- **供給の作り方**：競合は「無料で食べられる」で数を集めるが、私たちは「現金報酬」と「実績が評価される（運営確認済み・理由つきマッチング）」で**質の高いCreator**を集める。人数で勝負しない。
- **解約対策**：競合の弱点（成果が見えない）を逆手にとり、来店単価・売上÷費用を毎月見せる。
