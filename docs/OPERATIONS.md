# 運営マニュアル — AI社員で回す前提

GOURMET DIARY は「アプリは1人で作れる範囲、運営は人手をかける」設計にする。
運営の人手は AI 社員（Claude のエージェント）を中心に、最終判断だけ人間が行う。
競合（ユニット・QUANT など）が人の営業・サポートで提供している部分を、AI 社員の数で上回る。

## 1. 全体の流れ

```
npm run ops                      # 全キューの件数と最古の日付
npm run ops -- <queue>           # 1つのキューの中身と次の作業
```

キューは「人の判断や連絡が必要な例外」だけを集める。順調な案件は出てこない。
Web では `/admin`（運営Inbox）にも同じ例外が出る。

## 2. 役割（AI社員の配置）

| 役割 | キュー | やること | 道具 | してはいけないこと |
|---|---|---|---|---|
| 実績読み取り | `insights` | Creatorの30日インサイトのスクショを読み、実績として登録 | skill `read-insights`、`npm run insights` | 数字の推測。読めなければ差し戻す |
| 投稿レポート読み取り | `post-reports` | PR投稿1本ごとのインサイトを読み、閲覧数・リーチ・保存などを登録 | skill `read-post-report`、`npm run post-reports` | 別の投稿の数字を登録すること |
| Creatorサポート | `post-reports-missing`、`posts-overdue` | 投稿から1週間たってもレポートがない／投稿期限を過ぎたCreatorに連絡 | 下のテンプレート | 罰則・報酬減額をほのめかす |
| 店舗サポート | `applications-waiting` | 応募が2日以上放置されている店舗に確認をお願いする | テンプレート | 店舗の代わりに採用を決める |
| マッチング | `campaigns-no-applicants` | 公開3日で応募0件の案件に、おすすめCreatorを招待。報酬・日程の見直し案を店舗に出す | `/restaurant/campaigns/<id>/applications` の「おすすめCreator」 | 店舗の許可なく条件を変える |
| 品質管理 | `reviews-low` | ★2以下の評価について双方に事情を聞き、記録して閉じる | `npm run ops -- followed-up <reviewId>` | 評価の削除・書き換え（できない設計） |
| 店舗開拓 | （キューなし） | Creatorから「DMで依頼が来た」と聞いたら、依頼受付ページのリンクを返すよう案内する。招待リンクが登録待ちのまま3日たった店舗には、相手に再送するよう案内 | `/restaurant/offers/invites`、Creatorの `/creator/profile` | 店舗やCreatorになりすましてDMを送る |
| 経理 | `payments-ready`、`fees` | 支払承認済みの報酬を振込予定・支払済みにする。月初に `npm run billing -- preview` で前月の手数料を確認し、人間の確認後に `send --yes` でStripeの請求書を送る。入金はWebhookで自動反映。期限切れの「請求済み」は店舗に連絡 | `/admin/payments`、`npm run billing`、`npm run ops -- fees`、`docs/BILLING.md` | Creator報酬の振込は必ず人間が実行。手数料の金額は変えない（初回無料は自動）。人間の確認なしに `--yes` で送らない |

人間が必ず行うこと：振込の実行、規約違反の判断（アカウント停止）、料金・規約の変更、トラブル時の最終回答。

## 3. 連絡テンプレート

送信手段（メール・LINE等）は人間が決める。AI社員は下書きまで作り、送信できる仕組みを渡された場合だけ送る。

**投稿レポートのお願い（Creator）**
> {Creator名}さん、{店舗名}のPR投稿ありがとうございました。投稿から1週間たちましたので、投稿の「インサイトを見る」画面のスクリーンショットを、アプリの予約詳細から送っていただけますか。閲覧数が運営確認済みとして店舗に届き、次の案件の実績にもなります。

**投稿期限のご確認（Creator）**
> {Creator名}さん、{店舗名}のPR投稿の期限（{期限}）を過ぎています。投稿済みでしたらURLの提出を、遅れそうでしたら目安の日をお知らせください。

**応募のご確認（店舗）**
> {店舗名}様、「{案件名}」に{n}件の応募が届いています。応募者は相性の良い順に並んでいますので、来店日時を1つ選ぶだけで確定できます。

**応募が来ない案件（店舗）**
> {店舗名}様、「{案件名}」の公開から3日たちました。おすすめのCreatorに招待を送りました。応募を増やすには、報酬を{提案額}に上げる、来店できる時間帯を増やす、のどちらかが効果的です。

**低評価の聞き取り**
> 先日のPR（{案件名}）について、評価にあった点を詳しく伺えますか。今後のマッチングの改善に使います。相手の方に個別のお名前やコメントをお伝えすることはありません。

## 4. 品質ルール

- 数字は画像に写っているものだけ。推測・補完はしない。
- 画像（スクショ）は店舗に見せない。作業後は `.insights-queue/` を削除する。
- 評価は双方が送るか14日たつまで相手に見えない。AI社員も相手に内容を漏らさない。
- 迷ったら人間に回す。「人の判断が必要」と書いて終える。

## 5. 1日の回し方（例）

| 時刻 | 役割 | 作業 |
|---|---|---|
| 9:00 | 全員 | `npm run ops` で件数確認 |
| 9:00〜 | 読み取り2役 | スクショのキューを0件にする |
| 10:00〜 | Creator・店舗サポート | 連絡の下書き → 人間が送信 |
| 11:00〜 | マッチング | 応募0件の案件に招待と提案 |
| 16:00 | 経理 | 支払いの状態を更新（振込は人間） |
| 17:00 | 品質管理 | 低評価の聞き取りを記録して閉じる |
| 18:00 | 全員 | 残件と人間の判断待ちを報告 |
