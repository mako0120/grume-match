# 商用公開チェックリスト

有償で一般公開する前に必要なことの一覧。**コードで済んでいるもの**と、**人間（必要なら専門家）が行うもの**を分けている。
取引フローの動作確認は `docs/PILOT_CHECKLIST.md`、手数料の請求は `docs/BILLING.md` を参照。

## 1. コードで対応済み

| 項目 | 内容 |
|---|---|
| 利用規約・プライバシーポリシー・特商法表記 | `/terms` `/privacy` `/legal`。全ページのフッターからリンク。運営者情報は環境変数からのみ表示し、未設定は「未設定」と出す |
| 規約への同意 | 登録時にチェック必須。メール確認後の初回ログイン・既存ユーザー・招待経由は `/terms/accept` で同意してからオンボーディング／アプリへ。版（`TERMS_VERSION`）ごとに `terms_acceptances` と監査ログに記録 |
| 広告であることの表示（ステマ規制） | 投稿URLの提出時に「PR表記をした」の確認が必須（DBでも拒否）。店舗の確認画面に確認状況と、表記のない投稿を承認しない旨を表示 |
| 報酬の扱い | Creatorへの報酬は店舗→Creatorの直接払い。運営は預からない（`docs/BILLING.md`） |
| 権限 | 取引データは当事者だけが読めるRLS。管理用の鍵はサーバーのみ |
| 公開準備の確認 | `/api/health` が `legal: "ok" / "incomplete"` を返す（変数名も値も出さない） |

## 2. 人間が行うこと（公開前に必須）

### 法務・税務
- [ ] **利用規約とプライバシーポリシーを弁護士に確認してもらう。** 現在の文面は実装に合わせた原案。特に、免責と責任の上限（第13条）、管轄（第15条）、手数料と返金（第5条）、退会（第11条）を確認する。文面を変えたら `lib/legal.ts` の `TERMS_VERSION` を施行日に更新する（全員に再同意を求める）。
- [ ] **特商法表記の情報を決めて、環境変数に設定する**（`.env.example` の `LEGAL_*` の5つ）。個人事業主で住所・電話番号を表示しない運用にしたい場合は、省略が認められる条件を満たすかを専門家に確認する。
- [ ] **電気通信事業の届出が必要かを確認する。** 現在は利用者同士の自由なメッセージ機能はないが、今後チャット等を加えると届出が必要になる可能性がある。
- [ ] 適格請求書発行事業者の登録と、請求書の記載を税理士に確認する（`docs/BILLING.md`「確認しておくこと」）。
- [ ] 委託先（Supabase・Vercel・Stripe）のデータ処理に関する契約・規約を確認し、サーバーの所在国をプライバシーポリシーの記載と合わせる。
- [ ] 個人情報の漏えい等が起きたときの手順（個人情報保護委員会への報告と本人への通知）と担当者を決めておく。
- [ ] 問い合わせ窓口のメールアドレスを、実際に誰かが受信して返信できる状態にする。

### 本番環境
- [ ] Supabase 本番プロジェクト：日本に近いリージョン、自動バックアップ（できればPITR）のあるプラン、全マイグレーションの適用。
- [ ] Supabase Auth：メール確認をON、Site URL とリダイレクトURLを本番ドメインに、**独自SMTP**を設定する（標準のメール送信は送信数の上限が低く本番向きではない）。
- [ ] Vercel：本番ドメイン、環境変数（`docs/SETUP.md`）、`NEXT_PUBLIC_SITE_URL`、`CRON_SECRET`。
- [ ] Stripe：本番モードへの切り替え、本番の税率ID・Webhook（`docs/BILLING.md`）。
- [ ] `/api/health` を外形監視に登録し、`ok: true` と `legal: "ok"` を確認する。
- [ ] 検索エンジンに載せるか決める。現在は全ページ `noindex`（`app/layout.tsx`）。集客に使うなら、トップや法務ページだけ公開するなどを決めて変更する。

### 公開直前
- [ ] `npm run check`・`npm run build`・`bash supabase/tests/run.sh` がすべて成功。
- [ ] `docs/PILOT_CHECKLIST.md` を本番と同じ構成の環境で一通り実施。
- [ ] 本番DBで、運営者アカウントだけが admin であることを確認。

## 3. まだ実装していないもの（次の候補）

| 項目 | 現状 |
|---|---|
| 退会（アカウント削除） | 規約上は「所定の方法で申し出」。現在は問い合わせを受けて運営が手動で対応する。請求記録など保存が必要なデータを残す設計が必要 |
| キャンセル・no-show の理由記録 | 予約の状態はあるが理由と手続きの画面がない |
| エラー監視サービス | Vercel のログのみ |
| Content-Security-Policy | 他のセキュリティヘッダーは設定済み。CSPは未設定 |
| ログイン試行などのレート制限 | Supabase Auth 側の制限に依存 |
