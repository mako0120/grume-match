# UX Flows v1

## 1. Creator — Apply in under 30 seconds

### Screen A: Campaign list

Card:
- 店舗名
- エリア
- ジャンル
- **現金報酬**
- 食事提供
- 募集人数
- 来店期間
- Instagram / TikTok等

Primary CTA:
**詳細を見る**

### Screen B: Campaign detail

上から:
1. 報酬
2. 提供内容
3. 必須投稿
4. 来店期間
5. 店舗/料理
6. 来店可能日時

Primary CTA:
**日時を選んで応募**

### Screen C: Tap Schedule

```
10/8
[18:00] [18:30] [19:00] [19:30]
[20:00] [20:30]
[19:00以降ならいつでも]

10/9
[18:00] [18:30] [19:00] [19:30]
[20:00] [20:30]
[19:00以降ならいつでも]
```

複数選択可能。

下部sticky:
- 選択候補: 3件
- 来店人数: [1名] [2名]
- **この候補で応募する**

## 2. Restaurant — Confirm with one tap

応募者カード:

```
グルメ日誌
Instagram 4,000

希望:
○ 10/8 19:00
○ 10/9 19:00
○ 10/11 19:00以降

[候補を見る]
```

候補詳細では、実際に現在空いているスロットだけ表示。

```
10/11
[19:00] [19:30] [20:00]
```

**19:30で採用する**

Confirm modal:
- Creator
- 日時
- 人数
- 報酬
- 必須投稿

**確定する**

## 3. Booking detail

Creator / Restaurant双方に同一の事実を表示。

- 店舗
- 来店日時
- 人数
- 報酬
- 提供内容
- 投稿内容
- 投稿期限
- 状態

Action:
- Calendarに追加
- 日時変更申請
- キャンセル申請
- 投稿URL提出

## 4. Reschedule

Creator:
**日時変更を申請**

現在空いているスロットだけ表示。

別スロットを選択 → 店舗へ通知。

店舗:
- 承認
- 却下

自由入力交渉は「候補が一つもない」場合だけ表示。

## 5. Restaurant campaign creation

Step form:

1. 店舗選択
2. PR内容
3. 現金報酬
4. 食事提供
5. 必須媒体
6. 募集人数
7. 来店可能日時
8. 投稿期限
9. Preview
10. Publish

日時入力はカレンダー + 時間帯 + 繰り返しルール。

例:
- 10/1〜10/31
- 月〜木
- 17:00〜21:00
- 30分刻み
- 1slot 1組

例外日を追加可能。

## 6. Creator dashboard

最上部:
- 次の来店
- 応募結果
- 投稿期限
- 入金待ち

下:
- おすすめ案件
- 高報酬
- 今週行ける

## 7. Restaurant dashboard

最上部:
**今日やること**

例:
- 応募者を選ぶ 3
- 日時変更申請 1
- 投稿確認 2

その下:
- 募集中
- 来店予定
- 投稿待ち
- 完了

## 8. Admin

トップはKPIグラフではなくInbox。

```
要対応 4件

[支払期限超過] Campaign #42
[投稿期限超過] Booking #18
[日程衝突] Booking #27
[通報] User #52
```

通常稼働中の案件は別タブ。

## 9. Mobile-first rules

- CTAは画面下部sticky
- 日時ボタンは44px以上
- 報酬をカードで最も目立つ数値にする
- 重要条件を折りたたみ内に隠さない
- 応募前に必須投稿と現金報酬を再表示
- 「無料」という語で食事提供と報酬を混同させない
