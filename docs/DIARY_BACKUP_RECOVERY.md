# グルメ日誌｜既存Google Driveでのバックアップ・復旧安全手順

**状態（2026-10-22）:** 実装と合成データの自動テストのみ。大学Googleアカウント、Google Sheets原本、共有設定は一切変更していません。自動バックアップは**存在せず**、手動作成機能も初期OFFです。

## 原則

管理表の原本は現在の「グルメ日誌｜PR案件管理ボード」のままです。移行用コピーを作る必要はありません。Netlify Formsの申込み原本とGoogle Sheetsの案件・入金記録は性質が異なるため、両方の完全性を確かめます。

現在の大学Googleアカウント内でのみコピーできる仕組みです。バックアップが原本と同じアカウントにあるため、**大学アカウント失効、Google Workspace管理者による削除、組織全体の停止には対応できません**。別の独立した保存先へのエクスポートは、大学のポリシーに従って別途検討・承認する必要があります。

## ステップ1｜読取り専用で点検（原本不変）

オーナーが実環境でApps Scriptを導入したあと、`SPREADSHEET_ID` に**既存管理表のID**を設定し、`previewDiaryBackup()` を手動実行します。返すのは各タブ名・行列数・SHA-256だけで、氏名や連絡先、金額はログへ出しません。シートが大きすぎる、必須タブがない場合は異常停止します。

プレビューはバックアップ作成の代わりではありません。原本が消えると指紋だけからデータは復元できません。

## ステップ2｜明示承認後、同じDriveに手動バックアップ（初期OFF）

**こちらで以下を実行したわけではありません。** 有効化の可否はオーナーが判断します。

1. 現在のGoogleアカウントの「マイドライブ」直下に、バックアップ専用フォルダを作る。一般公開・グループ/他ユーザー共有を設定しない。
2. Apps ScriptのScript Propertiesに `DIARY_BACKUP_FOLDER_ID` を設定する。Webページ、GitHub、Sheetセルには書き込まない。
3. Script Propertiesで `DIARY_BACKUP_ENABLED=true` と明示した場合だけ、`createDiaryBackup()` を**手動で1回実行**する。
4. コードは実行者・原本ファイル・バックアップフォルダの所有者一致、直下のプライベートフォルダ、共有の有無を検証し、Google Sheetsの全タブをコピーする。
5. コピー先も非共有であることを検証し、原本前後とコピーの内容・数式・タブ構成をSHA-256照合。一致した場合だけ最新のバックアップIDと検証時点をScript Propertiesへ保存。不一致なら作成コピーをゴミ箱へ移す。
6. 必ず `verifyDiaryBackup(バックアップID)` で再検証し、バックアップファイルが「制限付き」であることをDriveでも目視確認する。
7. 不要になれば `DIARY_BACKUP_ENABLED=false` に戻す。自動トリガーは設置されません。

コピーは担当者情報・相談内容・金額を含むため、取扱いに注意してください。毎回実行するたびにコピーが増えるため、保存期間と削除手順も別途運用判断が必要です。大学Workspace管理者による暗黙のアクセス権をスクリプトだけで完全に否定できません。

## ステップ3｜復元前照合（読取り専用）

直近の記録済みバックアップに対して `verifyDiaryBackup(id)` は改ざん・欠損を確認します。 `planDiaryRestore(id)` は**バックアップと現在の原本の差分があるタブ名だけ**を返します。顧客の個々の行をチャットやログに転記しません。

**これらの関数は復元しません。原本に上書きしません。** 復元する場合は隔離したテスト環境でバックアップを検証し、元の申込ID、請求金額、入金記録、変更履歴の整合を見て、実原本への反映はオーナーが別途承認します。新着申込の消失を防ぐため、安易なシート全体の置換は避けます。

## 合格判定と障害時対応

- 必須タブ（`01_案件ボード`、`07_自動受付`）と数式を含む全タブが一致。
- コピーの所有者・フォルダの所有者は現在接続しているGoogleアカウントで、個別共有・一般公開がない。
- バックアップのSHA-256が作成時点の記録と一致。
- 原本は変更なし。新しい申込みや手動編集との差分を「復元が必要」と自動判定しない。
- 署名・権限・ネットワーク障害、コピー不一致、復旧失敗時は**自動操作を停止**し、Netlify Forms原本とGoogle Sheetsの変更履歴を別々に照合する。

実環境での復元演習は**未実施**です。合成データの単体テストは本番復元の成功証明ではありません。
