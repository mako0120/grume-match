# 競合比較 — GOURMET DIARY PR OS は何が違うのか

調査日: 2026-10-03。各社の公開情報・プレスリリース・比較記事をもとにまとめた（出典は末尾）。
料金や機能は変わるため、営業資料に使う前に各社サイトで最新情報を確認すること。
各社の稼ぎ方（ビジネスモデル）と料金案は `docs/BUSINESS_MODEL_ANALYSIS.md`。

## 1. 市場の全体像

飲食店×グルメインフルエンサーのマッチングは、大きく4つの型に分かれる。

| 型 | 代表例 | 店舗の払い方 | インフルエンサーへの対価 |
|---|---|---|---|
| 定額・依頼し放題（ギフティング中心） | QUANT for Shops / tags-Restaurant / ユニット | 月額定額（5,000円〜3万円〜） | 主に食事の無償提供 |
| 無料〜低額の招待型 | モグカツ | 無料プランから | 「レセプション」で料理・サービスを無料体験 |
| 1人単価のキャスティング型 | FOODee IM / グルキャス / PR会社 | 初期費用＋1人あたり費用 | 案件ごと（従来は店舗→PR会社に3〜15万円、インフルエンサーは無償飲食が主流） |
| 総合DX・代理店型 | GATE ほか | パッケージ | 施策ごと |

## 2. 業界の共通課題（公開記事から）

1. **来店につながったか分からない** — 投稿が来店・売上につながったかを数値で把握しにくい。インフルエンサーは「いいね・再生」、店舗は「来店」を成果と考え、ズレが起きる。
2. **無償招待が主流** — 対価は食事のみの案件が多い。「無料で食べさせてくれたら投稿する」と営業する"自称"インフルエンサーや、店舗名をかたる業者のDMも報告されている。
3. **DMでの調整・投稿されないリスク** — 日程や条件をDMでやり取りし、投稿されないこともある。
4. **ステマ規制（2023年10月〜）** — 金銭だけでなく、食事の無償提供で投稿を依頼した場合も「対価性のある広告」とみなされる可能性が高い。違反の責任は**店舗（広告主）**にある。
5. **二次利用のトラブル** — 投稿の著作権は原則インフルエンサーにある。二次利用は範囲・期間を契約で決める必要があり、トラブルが多い項目。相場は投稿報酬の20〜50%、または3か月でフォロワー数×1〜2円。

### 意図的にやらないこと
- **Googleマップ・食べログ等への口コミ投稿依頼**：見返りつきの口コミはGoogleのポリシーで禁止されており、ステマ規制上も店舗のリスクが大きい。SNSのPR投稿（PR表記つき）だけを扱う。
- **予約機能**：予約は店舗の今のやり方のまま。来店はPRコードで記録する。
- **DM・チャット**：日程はタップ、条件は案件に構造化。連絡が必要な例外は運営（AI社員）が拾う。

## 3. GOURMET DIARY だけの強み

公開情報で確認できる範囲では、競合は「たくさん来てもらう（量）」に強い。GOURMET DIARY は**「有償PRを、DMなしで、来店成果まで一貫して回す」**ことに特化している。

| # | 強み | 中身（このリポジトリでの実装） | 競合との違い |
|---|---|---|---|
| 1 | **現金報酬が必須** | 現金報酬0円では公開できない（DBで強制、`202609300013_paid_campaign_guard.sql`）。食事提供とは別に金額を明示 | 主流は無償招待・定額依頼し放題。真剣なCreatorが集まり、店舗は対価と「PR表記」が前提の、ステマ規制に沿った運用になる |
| 2 | **日程はタップで確定、DMなし** | 候補枠タップ／「19時以降ならいつでも」応募 → 店舗が1タップで確定。二重予約防止、日時変更もタップ（`docs/UX_FLOWS.md`） | 公開情報では、来店日時を構造化して自動で衝突回避する仕組みは確認できなかった |
| 3 | **理由を説明できるマッチング** | 30日の閲覧実績・大阪／兵庫での投稿実績・PR完了数・無断キャンセル・ジャンル・希望報酬で点数化し、理由を表示。公開時に相性の良い人へ自動招待（`docs/MATCHING.md`） | 競合は条件での絞り込み・一斉通知が中心。「なぜこの人か」を毎回示す仕組みは確認できなかった |
| 4 | **実績を運営が確認** | Creatorはインサイトのスクショを送るだけ。運営（またはClaude）が読み取り「運営確認済み」に。編集すると確認は外れる（`docs/CREATOR_PERFORMANCE.md`） | 「自称インフルエンサー」問題への直接の答え。フォロワー数ではなく直近30日の閲覧で選べる |
| 5 | **来店まで計測** | Creator別リンクの閲覧数と、口頭で伝えられる「PRコード」で来店を記録。来店単価・売上÷費用を表示。予約機能は持たない（予約は店舗の今の方法のまま）。Cookie・IP等は保存しない（SIGNAL） | 業界最大の課題「来店につながったか分からない」に、個人情報なしで答える |
| 6 | **二次利用を条件として構造化** | 範囲（自社SNS・Web／＋広告）・期間（30/90/365日のみ）・料金を案件に明記。承認日から期間が始まり、期限後は素材が開けなくなる（STUDIO） | トラブルの多い二次利用を、契約書なしでも明確にできる |
| 7 | **応募後は条件を変えられない** | 報酬・日程・納品物・二次利用は最初の応募後にロック | 「後から条件が変わる」不信を防ぐ |
| 8 | **報酬の支払い状態が見える** | 承認済み→振込予定→支払済みを区別し、Creatorのウォレットに表示 | 有償PRに必要な「払ったか」の透明性 |
| 9 | **相互評価が公平** | PR完了後に双方が★と項目で評価。双方が送るか14日たつまで非公開、変更不可。★2以下は運営が聞き取り | ユニットにも相互評価はあるが、報復・忖度を防ぐ仕組みは確認できなかった |
| 10 | **投稿ごとの閲覧数を運営が確認** | Creatorは投稿のインサイトのスクショを送るだけ。運営（AI社員）が読み取り、店舗に閲覧数・閲覧した人・保存・1,000閲覧あたり費用を表示 | QUANTはリーチ数を表示。私たちは自己申告でなく確認済みの数字を、費用と並べて出す |

一言でいうと：**競合は「無料・定額で量を集める」。GOURMET DIARY は「有償で、合う人を、DMなしで、来店成果まで」。**

| 決済 | 手動（振込は運営が外部で実施） | — |
| 地域 | 大阪から開始（密度を優先。兵庫は実績判定のみ） | 全国・都市部 |

## 5. ポジショニングと打ち手

- **狙う店舗**: 無償招待で「来たけど来店が増えなかった」「投稿されなかった」「DM対応がつらい」経験がある個店〜小規模チェーン。
- **狙うCreator**: 現金報酬で継続的に活動したい、地域に強いマイクロCreator（例: グルメ日誌＝大阪・淡路で直近30日 約12.4万閲覧）。
- **価格の論点**: 無償・定額の競合と同じ土俵で戦わない。「1来店あたりいくらか」（SIGNALの来店単価）で比較してもらう。プラットフォーム手数料の設計（月額か、報酬の◯%か）は別途決める。
- **トップページでの伝え方**: 他社名は出さず、「一般的な無償招待型」との違いとして、①現金報酬 ②タップで日程 ③理由つきマッチング ④来店まで計測 ⑤二次利用の明確化 を示す（`app/page.tsx`）。
