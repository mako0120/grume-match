# gourmet-ui-quality

## 体験設計
「今日やること」「ステータス」「来店予定」「投稿」「売上/未入金」を第一階層で見せ、案件詳細は必要な時だけ開く。
- 360px/768px/1440px幅で検証、横スクロール最小、読みやすい10〜16px以上のラベルと適切なコントラスト。
- 進捗は色のみに依存しない。空状態・読込中・同期エラー・期限切れ・権限なしを明示。
- モーダルはフォーカス移動・Escape閉鎖・適切なariaを実装。入力にはlabelと検証メッセージを用意。
- React hooksの依存、二重送信、余分な再レンダリング、レイアウトシフトを点検する。
- デモ案件と本物の案件を混在させない。金額・投稿URL・入金情報の偽表示をしない。
- 大きなライブラリを導入する前に既存のNext.js / Reactで実装可能か検討し、依存先の脆弱性とバンドルサイズを比較する。
## 検証
typecheck、eslint、unit、build、実際のPC/スマホのUI表示。ブラウザの実表示未確認なら「見た目の検証は未完了」と明示。
